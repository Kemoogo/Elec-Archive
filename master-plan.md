## 🎨 Stitch MCP — دوره في المشروع

**Stitch MCP** هو Google Labs tool بيولّد UI designs وكود HTML/CSS من natural language prompts، ومتكامل مع Claude Code كـ MCP server.

### ⚠️ قاعدة إلزامية:

**يجب استخدام Stitch MCP server مباشرة لتوليد كل شاشة — لا يُسمح بالاعتماد على ملفات artifacts مسبقة أو تصميمات يدوية.**

كل مهمة Stitch في أي Phase يجب أن تستدعي أدوات MCP الحية:
- `stitch_create_project` — إنشاء مشروع جديد
- `stitch_generate_screen_from_text` — توليد شاشة من prompt نصي
- `stitch_list_screens` — عرض الشاشات المولّدة
- `stitch_get_screen` — استخراج تفاصيل شاشة محددة
- `stitch_create_design_system` — إنشاء Design System
- `stitch_apply_design_system` — تطبيق Design System على شاشات

### طريقة الاستخدام في كل Phase:

```
لكل صفحة / component جديدة:

1. DESIGN  → استدعاء Stitch MCP server مباشرة:
             stitch_create_project → stitch_generate_screen_from_text
             مع prompt يصف الشاشة بالتفصيل

2. EXTRACT → استخراج البيانات من الشاشات المولّدة:
             stitch_list_screens → stitch_get_screen
             لاستخراج Design DNA و component structure

3. CONVERT → تحويل الـ HTML/CSS لـ Next.js components
             (Tailwind CSS + shadcn/ui مع RTL support)

4. CONNECT → ربط الـ component بـ API Routes + Mongoose
```

### Stitch MCP Config (Claude Code):
```json
{
  "mcpServers": {
    "stitch": {
      "command": "npx",
      "args": ["-y", "stitch-mcp"],
      "env": {
        "GOOGLE_CLOUD_PROJECT": "YOUR_PROJECT_ID"
      }
    }
  }
}
```

### الـ Design System (يُستخرج من Stitch مرة واحدة في Phase 0):
- نستدعي `stitch_create_project` لإنشاء مشروع Stitch
- نستدعي `stitch_generate_screen_from_text` لتوليد شاشة Dashboard رئيسية
- نستدعي `stitch_get_screen` لاستخراج Design DNA: ألوان، خطوط، spacing
- نحفظه في `DESIGN.md` → يُستخدم في كل الشاشات التالية للاتساق

## 👥 الأدوار والصلاحيات (Roles & Permissions)

### 1. Admin (مدير النظام)
- إدارة المستخدمين وإنشاء الحسابات
- تحديد صلاحيات كل موظف على كل قسم
- عرض الـ Audit Log الكامل
- الوصول لكل الأقسام

### 2. القائد (Commander)
- Dashboard رئيسي يعرض ملخص كل الأقسام
- استقبال تنبيهات الفاكسات الجديدة (Real-time via WebSocket)
- اتخاذ قرارات على الفاكس
- عرض التمام اليومي بعد الـ Submit
- View + Action على المهام الموجهة إليه

### 3. Employee (موظف)
- صلاحيات مختلفة لكل قسم حسب تعيين الـ Admin
- رفع وتعديل وعرض البيانات الخاصة بقسمه فقط

### 4. Viewer (مشاهد)
- قراءة فقط — لا يستطيع إضافة أو تعديل

## 🛡️ معايير الجودة والأمان (Security & Quality Standards)

### 1. الأمان (Security-First)
- **Authentication:** استخدام JWT مؤمن (HttpOnly Cookies) لمنع الـ XSS والـ CSRF.
- **RBAC:** التحقق من الصلاحيات في كل API Route وفي الـ Server Layouts.
- **Input Sanitization:** لا نثق بأي إدخال من المستخدم؛ يتم فحص وتطهير كل البيانات قبل إرسالها لـ MongoDB.
- **Audit Logging:** أي عملية (إنشاء، تعديل، حذف) يتم تسجيلها فوراً في الـ `AuditLog` مع تسجيل رقم الـ IP واسم المستخدم.
- **Rate Limiting:** تطبيق حد أقصى لمحاولات تسجيل الدخول والطلبات لمنع الـ Brute-force.
- **No Self-Registration:** يُمنع التسجيل الذاتي (Self-Registration) نهائياً؛ إنشاء الحسابات يتم حصرياً عبر الـ Admin Panel لضمان سرية النظام.

### 2. فلسفة التطوير (Architecture Policy)
- **SSR-First Policy:** يتم استخدام **React Server Components (SSR)** بشكل افتراضي لكل الصفحات. 
- **Minimal Use Clients:** لا يتم استخدام دستور `'use client'` إلا عند الضرورة القصوى (مثل النماذج التفاعلية Forms أو الـ Charts).
- **Edge Cases:** في كل موديول، يجب معالجة حالات مثل:
    - فشل الاتصال بقاعدة البيانات.
    - محاولة الوصول لمستند محذوف أو غير موجود (404 handling).
    - رفع ملفات بصيغ غير مدعومة أو أحجام ضخمة جداً.
    - التعامل مع التعديلات المتزامنة (Concurrency) من مستخدمين اثنين.

### 3. الجودة والاختبار (Quality Control)
- **Linting & Formatting:** الالتزام بقواعد ESLint و Prettier لضمان توحيد شكل الكود.
- **Build Validation:** لا يتم اعتماد أي كود (Merge) إلا بعد تخطي مرحلة `npm run build` بنجاح دون أي Errors أو Warnings.
- **Type Safety:** استخدام TypeScript بشكل صارم ومنع استخدام `any` نهائياً.
- **Validation:** استخدام مكتبة مثل `Zod` للتحقق من بيانات الـ Forms والـ API.

## 🗄️ Mongoose Models

### User
```typescript
{
  username: String,
  password: String (hashed),
  fullName: String,
  role: enum['admin', 'commander', 'employee', 'viewer'],
  department: String,        // القسم المعين عليه
  permissions: {
    fax: enum['none','view','edit'],
    officers: enum['none','view','edit'],
    medical: enum['none','view','edit'],
    students: enum['none','view','edit'],
    education: enum['none','view','edit'],
  },
  isActive: Boolean,
  createdAt, updatedAt
}
```

### Fax
```typescript
{
  faxNumber: String,
  date: Date,
  fromEntity: String,        // الجهة المرسِلة
  toEntity: String,          // الجهة المستقبِلة
  subject: String,
  fileUrl: String,           // مسار الملف المحلي
  fileType: enum['pdf','image'],
  status: enum['pending','decision_made','forwarded','closed'],
  commanderDecision: String,
  forwardedTo: String,
  relatedFaxes: [ObjectId],  // الفاكسات المرتبطة (thread)
  uploadedBy: ObjectId,
  createdAt, updatedAt
}
```

### Officer
```typescript
{
  militaryId: String,
  fullName: String,
  rank: String,
  position: String,          // الوظيفة الحالية
  joinDate: Date,
  documents: [{ name, fileUrl, uploadedAt }],
  isActive: Boolean,
  createdAt, updatedAt
}
```

### Leave (إجازة/غياب)
```typescript
{
  officerId: ObjectId,
  type: enum['annual','sick','mission','absence'],
  startDate, endDate: Date,
  reason: String,
  status: enum['pending','approved','rejected'],
  createdAt, updatedAt
}
```

### Assignment (تكليف/مأمورية)
```typescript
{
  officerId: ObjectId,
  type: enum['promotion','assignment','mission'],
  description: String,
  date: Date,
  createdAt, updatedAt
}
```

### DailyRollcall (التمام اليومي)
```typescript
{
  date: Date,
  submittedBy: ObjectId,
  submittedAt: Date,
  entries: [{
    officerId: ObjectId,
    status: enum['present','absent','leave','mission'],
    note: String
  }],
  isSubmitted: Boolean,
  viewedByCommander: Boolean,
  createdAt
}
```

### Patient (سجل طبي)
```typescript
{
  patientId: String,         // رقم الفرد
  patientName: String,
  visitDate: Date,
  diagnosis: String,
  treatment: String,
  dispensedMedicines: [{
    medicineId: ObjectId,
    quantity: Number
  }],
  createdAt, updatedAt
}
```

### Medicine (دواء/مخزون)
```typescript
{
  name: String,
  unit: String,
  quantity: Number,          // الكمية الحالية
  expiryDate: Date,
  minThreshold: Number,      // الحد الأدنى للتنبيه
  createdAt, updatedAt
}
```

### Student (طالب)
```typescript
{
  studentId: String,
  fullName: String,
  enrollDate: Date,
  documents: [{ name, fileUrl, uploadedAt }],
  notes: String,
  createdAt, updatedAt
}
```

### Course (دورة/تدريب)
```typescript
{
  title: String,
  description: String,
  startDate, endDate: Date,
  status: enum['upcoming','ongoing','completed'],
  participants: [ObjectId], // Officers أو Students
  documents: [{ name, fileUrl }],
  createdAt, updatedAt
}
```

### Notification (إشعار)
```typescript
{
  userId: ObjectId,          // المستخدم المستهدف
  type: String,              // 'new_fax' | 'rollcall_submitted' | 'medicine_expiry'
  title: String,
  body: String,
  isRead: Boolean,
  refId: ObjectId,           // مرجع العنصر (فاكس، دواء...)
  refModel: String,
  createdAt
}
```

### AuditLog (سجل العمليات)
```typescript
{
  userId: ObjectId,
  userName: String,
  action: String,            // 'CREATE' | 'UPDATE' | 'DELETE' | 'VIEW'
  module: String,            // 'fax' | 'officers' | ...
  targetId: ObjectId,
  description: String,
  ipAddress: String,
  createdAt
}

## ⚙️ Docker Compose (Production)

```yaml
version: '3.8'
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - MONGODB_URI=mongodb://mongo:27017/elec-archive
      - JWT_SECRET=${JWT_SECRET}
      - UPLOAD_PATH=/app/public/uploads
    volumes:
      - ./public/uploads:/app/public/uploads
    depends_on:
      - mongo
    restart: unless-stopped

  mongo:
    image: mongo:7
    volumes:
      - mongo_data:/data/db
    restart: unless-stopped
